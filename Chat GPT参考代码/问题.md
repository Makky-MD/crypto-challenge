## 1. 题目到底要求什么

目标是对一个巨大矩阵连乘积的单个元素做逼近：

\[
M(r)[v,u]
\]

其中每一轮由 3 个矩阵组成：

1. S 盒层：\(C^S \otimes C^S \otimes \cdots \otimes C^S\)，共 8 个 4-bit S 盒。
2. SR 线性置换层。
3. MC 线性混合层。

因此 \(3r\) 个矩阵对应 \(r\) 轮密码置换 \(HS(r)\) 的相关矩阵。换成密码分析语言，题目要估计：

\[
M(r)[v,u] =
2^{-32}\sum_{x \in \mathbb F_2^{32}}
(-1)^{u^\top x \oplus v^\top HS(x)}
\]

也就是输入掩码 \(u\)、输出掩码 \(v\) 下的线性相关度。

## 2. 参赛提交需要包含什么

题面要求提交：

1. 方式 2 的详细逼近算法及复杂度分析。
2. 一个 txt 文档，逐行记录有效估计值，格式类似：

   ```text
   @(r, u, v, V_T, V_E)
   ```

   或者如果可以写成集合形式，也可以写集合表达式。

3. 生成该 txt 文档的完整可运行程序。
4. 按评分公式自己计算的总分。

注意：txt 里的 \(V_E\) 必须来自逼近算法，不能把官方精确计算结果硬编码进去，否则得分为 0。

## 3. 有效估计值条件

题面给出的有效条件是：

\[
V_E \in [V_T - V_T 2^{-2},\ V_T + V_T 2^{-2}],\quad
V_E \ne 0,\quad u \ne 0,\quad v \ne 0
\]

这里 \(2^{-2}=1/4=25\%\)，不是 5%。原先草稿里写的 `0.05·V_T` 是错的。

如果 \(V_T < 0\)，题面这个区间写法会出现左右端点顺序反转。实际实现和文档里建议按相对误差解释：

\[
|V_E - V_T| \le |V_T|/4
\]

这个解释更符合“估计值接近真实值”的本意。

## 4. 评分公式的直接含义

每个有效估计值得分：

\[
\log_2(2^{2^r}\cdot |V_E|)=2^r+\log_2|V_E|
\]

如果某个逼近值大约是 \(V_E=\pm 2^{-w}\)，则得分约为：

\[
2^r-w
\]

所以解题策略不是单纯让 \(r\) 越大越好，而是要在轮数 \(r\)、可找到的高相关路线权重 \(w\)、以及真实线性壳叠加效果之间折中。

## 5. 已确认的 S 盒相关性质

S 盒：

```text
S = [C, 6, 9, 0, 1, A, 2, B, 3, 8, 5, D, 4, E, 7, F]
```

对 4-bit 输入掩码 \(a\)、输出掩码 \(b\)，S 盒相关为：

\[
C^S[b,a] = 2^{-4}\sum_x (-1)^{a^\top x \oplus b^\top S(x)}
\]

用脚本检查 LAT 后，非零相关分布为：

```text
非零项：133 / 256
相关分子分布：-8 有 17 项，-4 有 52 项，+4 有 44 项，+8 有 19 项，+16 有 1 项
```

因此非零相关只可能是：

```text
+1       对应 a=0,b=0
±1/2     对应 LAT 分子 ±8，路线权重 1
±1/4     对应 LAT 分子 ±4，路线权重 2
```

路线贡献可以写为：

\[
\text{cor(path)}=\text{sign}\cdot 2^{-w}
\]

其中 \(w\) 是每轮 8 个 S 盒权重的总和。搜索 Top-K 高贡献路线，本质就是搜索低权重线性路线，并保留符号叠加。

## 6. 推荐主方案：Top-K 线性路线叠加

核心思想：

1. 预计算 S 盒 LAT。
2. 每个 S 盒转移记录：
   - 输入掩码 \(a\)
   - 输出掩码 \(b\)
   - 符号 sign
   - 权重 weight，取值 0、1、2
3. 对 32-bit 掩码按 8 个 nibble 拆分。
4. 一轮路径为：
   - 输入掩码进入 S 盒层；
   - 每个 nibble 选择一个非零 LAT 转移；
   - 经过 SR；
   - 经过 MC；
   - 得到下一轮掩码。
5. 一条 \(r\) 轮路线从 \(u\) 到 \(v\)，贡献为所有 S 盒转移相关的乘积。
6. 取 Top-K 条路线，代数求和：

   \[
   V_E=\sum_{i=1}^K \text{cor(path}_i)
   \]

注意：必须带符号相加，不能把绝对值相加。

## 7. 实现路线 A：CaDiCaL SAT 版本

需要先明确：CaDiCaL 是 SAT 求解器，不是优化器。它只能判断 CNF 是否可满足，不能直接 `maximize`。所以 Top-K 需要通过外层程序反复调用 SAT 来实现。

### 7.1 变量设计

对第 \(t\) 轮、第 \(j\) 个 S 盒：

- \(a_{t,j}\)：4-bit S 盒输入掩码。
- \(b_{t,j}\)：4-bit S 盒输出掩码。
- \(w_{t,j}\)：该 S 盒转移权重，0/1/2。
- \(s_{t,j}\)：该转移符号，0 表示正，1 表示负。

对第 \(t\) 轮整体：

- \(X_t\)：该轮输入 32-bit 掩码。
- \(Y_t\)：S 盒层输出 32-bit 掩码。
- \(Z_t\)：SR 后掩码。
- \(X_{t+1}\)：MC 后掩码。

边界条件：

```text
X_0 = u
X_r = v
u != 0
v != 0
```

### 7.2 S 盒约束

对每个 S 盒，用 LAT 允许表编码：

```text
(a,b) 必须属于 LAT 非零集合
```

编码方法：

1. 枚举所有非法 `(a,b)`，为每个非法组合加入一个排除子句。
2. 或者为每个合法转移建一个 selector 变量，约束恰好选择一个 selector，并用 implication 绑定 `(a,b,weight,sign)`。

第二种更适合 Top-K，因为后续可以更容易排除已经找到的路径。

### 7.3 线性层约束

SR 和 MC 都是线性映射。SAT 编码时直接把输出 bit 写成输入 bit 的 XOR：

```text
out_bit = xor(in_bit_i, in_bit_j, ...)
```

CNF 中 XOR 可用 Tseitin 变量展开。更简单的工程实现是先用 PySAT 的 `CNFPlus` 或自己写 XOR-to-CNF 工具函数。

重要：MC/SR 的具体方向必须和官方 `computecor.cpp` 对齐。题面 OCR 中 3.4 的 MC 公式和 C++ 代码存在可疑不一致，最终应以官方代码和 2.3 矩阵定义复核。

### 7.4 优化目标

目标是按路线绝对贡献从大到小找 Top-K，即最小化：

\[
W=\sum_{t,j} w_{t,j}
\]

因为贡献绝对值为 \(2^{-W}\)。

CaDiCaL 实现优化的常用办法：

1. 给定权重上界 \(B\)，加入约束 \(W \le B\)。
2. 从小到大枚举 \(B=1,2,3,\dots\)，找到可行解。
3. 找到一条路径后加入 blocking clause，排除这条完整路径。
4. 继续求解，直到得到 K 条，或者达到时间/权重上限。

权重只有 0/1/2，可以把每个转移权重拆成若干布尔代价变量，再用顺序计数器、totalizer 或 cardinality network 编码 \(W \le B\)。

### 7.5 Top-K 伪代码

```text
routes = []
for B in range(0, B_max + 1):
    build CNF for:
        X_0 = u
        X_r = v
        valid LAT transitions
        SR/MC propagation
        total_weight <= B
        exclude all routes in routes

    while SAT and len(routes) < K:
        model = solve()
        route = decode(model)
        contribution = signed_product(route)
        routes.append(route)
        add_blocking_clause(route)

    if len(routes) >= K:
        break

V_E = sum(route.contribution for route in routes)
```

### 7.6 复杂度

设每次 SAT 求解平均耗时为 \(T_{\text{SAT}}(r,B)\)，则：

\[
O(K\cdot T_{\text{SAT}}(r,B))
\]

变量和约束数量随 \(r\) 近似线性增长。与官方精确计算的 \(O(r\cdot 2^{32})\) 次置换枚举相比，SAT 搜索低权重路线通常远低于方式 1，但需要在文档中给出实际测试时间、K、B、r。

## 8. 实现路线 B：MILP 版本

MILP 更适合“最小权重路径”问题，推荐用 Gurobi；如果没有许可证，可以尝试 OR-Tools CP-SAT，但 CP-SAT 更接近 SAT/伪布尔。

变量：

- 每轮每个 nibble 的输入/输出掩码 bit。
- 每个合法 LAT 转移一个二进制 selector。
- selector 绑定转移权重和符号。

约束：

```text
每个 S 盒恰好选择一个合法 LAT 转移
SR/MC 线性传播
X_0 = u, X_r = v
```

目标：

```text
minimize total_weight
```

Top-K 做法：

1. 求一次最优路线。
2. 加入 no-good cut 排除该路线。
3. 继续求解，得到第 2、3、...、K 条路线。

MILP 的优点是写法直观，直接支持目标函数；缺点是依赖 Gurobi/SCIP/CPLEX 等求解器。

## 9. 实现路线 C：STP / SMT 版本

STP 是位向量求解器，适合把掩码传播写成 bit-vector 公式：

```text
X_{t+1} = MC(SR(Y_t))
```

但它不擅长原生优化。可行做法类似 SAT：

1. 固定权重上界 \(W \le B\)。
2. 用位向量和数组/ITE 表示 LAT 合法转移。
3. 枚举 B 或用二分搜索找到可行低权重路线。
4. 加 blocking constraint 反复找 Top-K。

STP 的优势是 XOR/位向量表达自然；劣势是 Top-K 和权重约束通常比 MILP 麻烦。

## 10. 更实用的工程起步方案：Beam Search / DP

虽然你当前重点想问 CaDiCaL SAT，但实际参赛建议先写一个不依赖求解器的 beam search 版本，用来快速出结果和验证求解器方向。

思路：

1. 从 \(u\) 出发逐轮扩展。
2. 每个状态保存：
   - 当前 32-bit 掩码；
   - 累计权重；
   - 累计符号；
   - 路径。
3. 每轮对每个 active nibble 扩展其 LAT 非零转移。
4. 经过 SR/MC 后合并到下一轮状态。
5. 每轮只保留 Top-B 个低权重状态。
6. 到第 r 轮筛选掩码等于 \(v\) 的路线，取 Top-K 叠加。

这个版本不是严格全局 Top-K，但实现快、可调参、能生成候选 \(u,v,r\)，也能反过来给 SAT/MILP 提供目标边界。

## 11. 建议的完整工作流

### 第一步：统一基础组件

写一个共享库，包含：

```text
Sbox
LAT[a][b] = numerator / 16
transition list by input nibble a
SR mask propagation
MC mask propagation
round mask propagation
signed route contribution
score calculation
validity check
```

所有 SAT/MILP/STP/Beam Search 都复用这些组件，避免每个版本各写一套导致方向错误。

### 第二步：复核线性层方向

必须用小规模测试确认：

```text
路线传播得到的单轮相关矩阵元素
```

和直接枚举 \(2^{32}\) 不现实，但可以做：

1. 对单个 S 盒直接对比 LAT。
2. 对 1 轮、低活跃掩码，比较路线叠加值和官方 C++ 精确值。
3. 对随机小样本检查 SR/MC 的转置传播方向。

### 第三步：先做 Beam Search 出候选

输出若干候选：

```text
(r, u, v, route_count, V_E)
```

再调用官方 C++ 得到 \(V_T\)，筛掉无效项。

### 第四步：实现 CaDiCaL Top-K

在 Beam Search 找到较好候选后，用 SAT 做更严格的 Top-K：

```text
fixed r,u,v
enumerate routes with total_weight <= B
blocking clause 排除已找到路线
sum signed contribution
```

### 第五步：实现 MILP 作为对照

如果 Gurobi 可用，MILP 最适合作为“同一建模的优化器版本”，便于和 SAT 结果互相校验。

### 第六步：生成提交 txt

程序最终输出：

```text
@(r, 0xuuuuuuuu, 0xvvvvvvvv, V_T, V_E)
```

并额外输出：

```text
score_i = 2^r + log2(abs(V_E))
total_score = sum(score_i)
```

## 12. 下一步具体代码任务

建议按这个顺序写代码：

1. `lat.py` / `lat.hpp`：生成 S 盒 LAT 和合法转移表。
2. `linear_layer.py` / `linear_layer.hpp`：实现 SR、MC 的掩码传播，并和 `computecor.cpp` 对齐。
3. `beam_topk.py`：无求解器版本，先跑出候选结果。
4. `verify.py`：调用或改造官方 C++，计算 \(V_T\) 并验证有效性。
5. `sat_topk.py`：生成 CNF，调用 CaDiCaL，做权重阈值枚举和 blocking。
6. `milp_topk.py`：Gurobi/OR-Tools 对照版本。
7. `make_submission.py`：汇总候选、验证、算分、输出 txt。

## 13. 当前判断

最稳妥的参赛路线不是只押 SAT，而是：

```text
Beam Search 找候选
SAT/CaDiCaL 枚举固定候选的 Top-K 路线
MILP 做交叉验证
官方 C++ 算 V_T
最后生成有效估计 txt
```

置信度：中高。主要不确定点是题面 OCR 对 MC/SR 公式存在疑似错位，后续写代码前必须以官方 C++ 和原 PDF 视觉内容复核线性层方向。
